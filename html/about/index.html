Methodology

How a result becomes a trusted recommendation

Trust Architecture

Security, data handling, and operational accountability

Security

  • Server-side session checks for protected endpoints.
  • Role and ownership checks before returning account data.
  • Rate limits on premium actions to reduce abuse.

Data Handling

  • Calculation payloads are stored per user with clear ownership boundaries.
  • Cached premium outputs use scoped keys by user and context hash.
  • Export/report generation uses the same trusted result source.

Method Integrity

  • Primary metric by calculator type drives compare and optimizer decisions.
  • Derived metrics and missing checklists are generated consistently per model.
  • Scenario ranking balances impact, simplicity, and baseline improvement.

Roadmap

  • Stronger benchmark packs for edge-case markets.
  • More visual explanation layers in Account deep dive.
  • Expanded reliability telemetry for user-facing trust diagnostics.

What Users Can Verify

Nothing is hidden behind "just trust us"

  • Input changes are displayed next to each scenario.
  • Result deltas are shown against the baseline run.
  • Mini-verdict and deep-dive stay consistent with the same payload.
  • Portfolio and compare views reuse the same calculator logic.

Decision Quality Standard

Every premium output should answer three questions:

  1. What moved?
  2. How much did it move?
  3. What should I run next?
